# 搜索召回与匹配模型分析

## 问题：当前模型的缺陷

### 现状
```
BOSS直聘搜索 "Go Kubernetes GPU"
  → BOSS 的关键词匹配算法过滤（第一层）
  → 返回 30 条/页
  → 本地技能评分（第二层）
  → 输出
```

### 问题本质：双层乘积导致召回严重衰减

设：
- 总岗位池 N ≈ 1,000,000
- 真正相关岗位 R ≈ 500（用户真正感兴趣的）
- BOSS 关键词召回率 `P(搜到|相关)` = α
- 本地技能匹配保留率 `P(通过|搜到)` = β

**双层过滤的实际召回率 = α × β**

当搜索词是 "Go Kubernetes GPU" 这种组合时：
- BOSS 是 **AND 匹配**：要求标题/JD 同时命中多个词
- 大量标题写成 "资深后端工程师"、"平台开发" 的好岗位被漏掉
- 实测 α ≈ 0.1-0.2（召回率很低）

**乘积效应：α × β ≈ 0.15 × 0.8 = 0.12**
意味着我们只能看到 12% 的真正相关岗位。

## 正确的事件模型

### 漏斗模型

```
总岗位池 (N)
   │
   ▼  [召回层] 尽可能宽泛，高召回率
大召回集 (L ~ 3000-5000)
   │
   ▼  [过滤层] 硬条件过滤（经验/地点/薪资/标题黑名单）
候选集 (C ~ 300-500)
   │
   ▼  [排序层] 技能加权评分
排序结果 (Top 50-100)
   │
   ▼  [补全层] 抓取详情页，精排
最终结果 (Top 30-40)
```

### 关键原则

**召回层的目标：穷尽相关候选，不怕假阳性**
- 用**单一、广谱**的关键词搜索
- **深度翻页**（至少 5-10 页）
- 多个关键词的结果做**并集**而非交集

**过滤层的目标：硬性不匹配的全部剔除**
- 经验要求 > 用户经验
- 薪资远超或远低用户预期
- 岗位类型黑名单（销售/测试/前端）
- 工作地点不在目标城市

**排序层的目标：按匹配度排序**
- 技能权重
- 标题相关性
- 公司类型偏好

## 新召回策略

### 单关键词广谱搜索

不要用 "Go Kubernetes GPU" 这种 AND 组合。改用单一核心词：

```python
RECALL_KEYWORDS = [
    "Golang",       # 所有 Go 后端的根入口（几千个岗位）
    "Kubernetes",   # K8s 相关
    "云原生",       # 云原生方向
    "GPU",          # GPU 相关
    "AI Infra",     # AI 基础设施
    "容器",         # 容器方向
    "算力",         # 算力平台
    "go-zero",      # 框架级关键词（命中精准）
    "后端 Go",      # 最常见组合
    "后端 Kubernetes",
]
```

每个关键词翻 5-10 页，每页 30 条。
理论总召回 ≈ 10 关键词 × 8 页 × 30 条 ≈ 2400 条（去重后 ≈ 800-1200 条）

### BOSS 直聘 URL 高级参数

BOSS 直聘支持 URL 参数预过滤，可以减轻后续本地过滤负担：

```
https://www.zhipin.com/web/geek/job?
  query={keyword}       # 关键词
  &city=100010000       # 城市（100010000=全国）
  &experience=103,104   # 经验（103=1年以内, 104=1-3年）
  &salary=405,406       # 薪资范围
  &degree=203,204       # 学历（203=本科, 204=硕士）
  &page={n}             # 页码
```

经验代码：
- `101` = 应届
- `102` = 1年以内
- `103` = 1-3年
- `104` = 3-5年
- `105` = 5-10年
- `106` = 10年以上

对初级岗用户：在 URL 里加 `experience=101,102,103` 限制经验，这一层是平台自带的精确过滤，比关键词匹配靠谱得多。

## 新过滤策略（硬条件）

### 1. 标题黑名单（直接剔除）

```python
TITLE_BLACKLIST = [
    # 非后端岗
    "销售", "商务", "BD", "渠道", "市场", "运营",
    "产品经理", "PM", "产品",
    "前端", "iOS", "Android", "flutter", "U3D",
    "测试", "QA", "自动化测试",
    # 非开发岗
    "实习",  # 保留校招
    "算法研究", "研究员", "博士后",
    "运维",  # 纯运维岗
    "DBA",
    # 职级过高
    "总监", "VP", "CTO", "首席", "总经理",
]
```

### 2. 经验要求过滤（软规则 + 硬上限）

```python
# 硬上限：5年以上直接剔除
# 软规则：1-3年优先，3-5年降级
MAX_EXP_YEARS = 5  # 用户 <1 年经验，超过 5 年要求直接跳过
```

### 3. 薪资范围

```python
# 月薪 K
SALARY_MIN = 15  # 最低
SALARY_MAX = 80  # 最高（避免诈骗岗）
```

## 新排序策略（精排）

### 技能加权（和之前一样）

```
score = Σ(matched_skill_weight) / Σ(all_skill_weight) × 100
```

### 额外加权因子

```python
def final_score(job):
    base = calc_skill_score(job.jd + job.title)

    # 标题直接命中核心词，额外加分
    title_bonus = 0
    if any(kw in job.title.lower() for kw in ["go", "golang"]):
        title_bonus += 5
    if any(kw in job.title.lower() for kw in ["kubernetes", "k8s", "云原生"]):
        title_bonus += 5
    if any(kw in job.title.lower() for kw in ["gpu", "算力", "ai infra"]):
        title_bonus += 8  # 核心差异化技能

    # 经验要求匹配度
    exp_bonus = 0
    lo, hi = parse_exp(job.experience)
    if lo is not None:
        if lo == 0:                  # 应届
            exp_bonus = 5
        elif lo <= 1:                # 1年以内
            exp_bonus = 5
        elif lo <= 3:                # 1-3年
            exp_bonus = 3
        elif lo >= 5:                # 5年+
            exp_bonus = -10          # 降权

    # 公司类型加权
    company_bonus = 0
    if any(c in job.company for c in ["字节", "腾讯", "阿里", "美团", "百度",
                                       "京东", "滴滴", "拼多多", "小米", "华为",
                                       "智谱", "月之暗面", "MiniMax", "阶跃",
                                       "DeepSeek", "硅基流动"]):
        company_bonus = 5

    return base + title_bonus + exp_bonus + company_bonus
```

## 数据流重新设计

```
Stage 1: 广谱召回
  - 10 个核心关键词
  - 每个翻 5 页
  - URL 参数限制经验 ≤ 3 年
  - 仅从列表页提取最小字段（title/company/href/exp）
  - 快速：~2-3 分钟

Stage 2: 硬过滤
  - 标题黑名单
  - 经验硬上限
  - 薪资范围
  - 去重

Stage 3: 粗排
  - 仅用 title + 列表页文本计算技能分
  - 排序取 Top 60

Stage 4: 精排补全
  - CDP 抓取 Top 60 详情页
  - 补全 JD 全文、公司名、薪资、城市
  - 用 JD 全文重新计算技能分
  - 应用加权因子
  - 排序取 Top 40

Stage 5: 输出
  - Excel 分 P0/P1/P2/P3 染色
  - 每条带完整 JD 摘要
```
